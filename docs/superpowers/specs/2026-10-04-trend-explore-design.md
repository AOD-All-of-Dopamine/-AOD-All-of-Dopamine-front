## 트렌드 화면 (T3′)

머리: "이번 주 트렌드" + 주 표시("10월 첫째 주") + "매일 아침 갱신". 섹션은 모두 **전체 폭**, 위에서 아래로:

### ① 분야별 1위 다섯 장 (`#hot` 위)
- 영화 · 시리즈 · 게임 · 웹툰 · 웹소설 각 플랫폼 1위(콘텐츠 연결된 행 중 가장 높은 순위). 큰 세로 카드(그림 + 아래 어둡게 + "영화 1위" · 제목 · 신호 한 줄). 게임은 세로 표지, 없으면 header 를 흐리게.
- 성인 작품은 순위 쿼리가 이미 뺀다.

### ② 지금 뜨는 Top 10 (`#hot`)
- 분야 칩(영화 · 시리즈 · 게임 · 웹툰 · 웹소설, 기본 = 오늘의 작품 분야 또는 게임) + **두 줄 목록**(순위 · 변동 · 포스터 · 제목 · 신호). "100위까지 ›" → 같은 화면 안에서 목록을 100위까지 펼친다(새 페이지 없음).
- 출처 표기: "국내 OTT 인기"(TMDB) · "스팀 최고 판매" · "네이버웹툰" · "네이버 시리즈" + 갱신 시각.
- **변동**: 2단계(순위 기록) 전에는 칸을 비운다(시안의 예시 값은 쓰지 않는다).
- "카카오웹툰 준비 중" 같은 준비 중 플랫폼은 노출하지 않는다.

### ③ 새로 나온 주목작 (`#new`)
- **분야마다 한 칸 · 2편**, 다섯 칸 나란히(좁으면 가로 스크롤). 포스터 아래 신호 한 줄 + **주목 이유 한 줄**(강조색): "리뷰 458개" · "1.2만명 평가" · "네이버웹툰 3위" · "10월 3일 시작".
- 고르기(분야 균형이 핵심 — 웹소설이 목록을 다 차지하지 않게):
  - 1단계(지금 데이터): 최근 2주 출시 중 — 게임 `review_count` 많은 순, 영화 · 시리즈 TMDB `vote_count` 많은 순(상세 attributes — 서버에서 고른다), 웹툰 · 웹소설 **오늘 순위에 오른 신작 먼저**, 없으면 최신순.
  - 3단계 뒤: 분야별 인기 점수 순.
- "새로 나온 전체 ›" → 분야 칩 + 날짜별 목록(지금 `/new` 의 목록을 트렌드 안 펼침으로). 날짜 목록도 **분야 칩 기본 = 전체가 아니라 분야별**(전체는 웹소설에 묻힌다).

### ④ 곧 나올 (`#upcoming`) — 세로 포스터 줄
- 2:3 포스터(게임 세로 표지) · 왼쪽 위 **D-day 배지**(어두운 바탕) · 제목 · "게임 · 10월 5일". 가로 스크롤 줄.
- 1단계: 지금 데이터(게임만). 분야 칩은 데이터가 있는 분야만 보인다. 0편 분야를 "없음"으로 늘어놓지 않는다.
- 4단계 뒤: Steam 인기 출시 예정 · TMDB 개봉 예정이 들어오면 **기대도 순**(인기 점수 → 날짜).

## 탐색 화면 (E1)

- 머리 "탐색" + 분야 칩(**전체** · 영화 · 시리즈 · 게임 · 웹툰 · 웹소설 — "전체"는 새로 생긴다: 테마 선반만 보이고 그리드는 분야를 고르면).
- **테마 선반**: 한 줄 = 제목 · 규칙 한 줄(회색) · "전체 ›"(그 테마 필터가 걸린 그리드로) · 포스터 가로 줄 12편.
  - 테마 = **저장된 필터 + 정렬**(프론트 상수 `EXPLORE_THEMES` — id · 제목 · 규칙 문구 · 분야 · 쿼리). 서버 목록 API 를 그대로 부른다.
  - 1단계 테마(지금 API 로 되는 것만): "리뷰 1만 이상 게임"(`reviewCountMin=10000`) · "넷플릭스 · 왓챠에서 볼 수 있는 시리즈"(`platforms`) · "완결 웹툰 몰아보기"(`status=완결`) · "이번 주 순위에 오른 웹소설"(순위 API).
  - 3단계 뒤 테마: "압도적 긍정 게임"(판정 필터) · "평점 8 이상 영화"(평점 필터 + 인기 정렬) · "정주행하기 좋은 시리즈"(평점 · 시즌 수).
  - 분야를 고르면 그 분야 테마만(2~4줄).
- 아래 **필터 + 그리드**(지금 화면 그대로, 가벼운 카드). **기본 정렬 = "인기 · 평가순"** — 3단계 전에는 게임만 `review_count` 내림차순으로 가능, 다른 분야는 지금 기본(최신 출시순) 유지.

## 로직 — 단계

### 1단계 — 화면 + 지금 데이터 (백엔드 변경 작음)
- 프론트: 메뉴 · 트렌드 · 탐색(E1 1단계 테마) · 내 보관함 · 옛 주소 이동 · 홈 링크 · 앱 탭.
- 백엔드: **`GET /api/works/releases/notable?days=14&perDomain=2`** — 분야별 주목작(위 1단계 고르기). 영화 · 시리즈 `vote_count` 는 attributes 라 서버에서 고른다(프론트가 상세를 수십 번 부르지 않게). 캐시 1시간.
- 게임 정렬 `sortBy=reviewCount`(게임 탭 한정, `game_contents.review_count` — 쿼리 빌더에 정렬 축 추가).

### 2단계 — 순위 기록 (변동 · NEW)
- 표 `external_ranking_daily(snapshot_date date, platform, platform_specific_id, content_id, ranking, PRIMARY KEY (snapshot_date, platform, platform_specific_id))` — 크롤러가 순위 저장 뒤 그날 한 벌을 넣는다(insert-if-absent). 보관 **90일**(매일 지난 것 삭제).
- API: 순위 응답에 `previousRanking`(어제 순위, 없으면 null = **NEW**) · 변동은 프론트가 계산. 첫 하루는 모두 NEW 가 되므로 **기록이 2일 쌓인 뒤**에 변동을 보인다(그 전엔 칸 비움).
- 덤: 웹툰 · 웹소설의 주목도 근거(최근 30일 순위 등장 횟수 · 최고 순위)가 생긴다 → 3단계.

### 3단계 — 분야별 인기 점수 (탐색 정렬 · 주목작 · 테마)
- `contents.popularity_score`(0~1, 분야 안 백분위) · `popularity_updated_at`. 매일 한 번 계산(API 서버 예약 작업, 분야마다 한 쿼리):
  - 게임: `log(review_count)` 백분위 × (긍정 비율 보정)
  - 영화 · 시리즈: `log(vote_count)` 백분위 × (평점 보정) — 이를 위해 TMDB `rating` · `vote_count` 를 attributes 에서 **`movie_contents` · `tv_contents` 열로 승격**(V6 의 `review_count` 승격과 같은 방식, 정렬 · 필터 가능)
  - 웹툰 · 웹소설: 최근 30일 순위 등장(2단계 기록) — 없으면 0
- 목록 API: `sortBy=popularity`, 평점 필터(`ratingMin` — 영화 · 시리즈), 판정 필터(`steamVerdict` — 게임). 탐색 기본 정렬을 모든 분야 "인기 · 평가순"으로.

### 4단계 — 출시 예정 넓히기
- 게임: Steam "인기 출시 예정"(상점 검색 `filter=popularcomingsoon`) appid 를 매주 수집 대기열에 넣는다(이미 있는 수집 경로 — 출시일 · 세로 표지가 함께 온다).

- 웹툰 · 웹소설: 예정 정보가 없어 하지 않는다(곧 나올 칩에서 빠진다).
- 곧 나올 정렬 = 인기 점수 → 날짜.

### 정정된 사실
- **탐색 정렬**: 분야를 고르면 `sortBy` 는 무시된다 — 필터 없으면 `findByDomainOrderByReleaseDateDesc`(`WorkApiService.java:159-162`), 필터 있으면 `WorksQueryBuilder.java:35` 의 `ORDER BY c.release_date DESC` 고정. 게임 탭은 늘 `releaseTo=오늘` 을 보내 필터 경로다. `Content.reviewCount` 는 **우리 사이트 리뷰 수**라 `sortBy=reviewCount` 는 쓰면 안 된다.
- **게임 리뷰 수 · TMDB 투표 수는 수집 때 굳는다**(재수집 없음 / 출시 후 7일까지). 운영: 최근 2주 게임 625편 최대 리뷰 13개 → `/releases/recent` 의 게임 하한(100)에 모두 걸려 **최근 한 달 게임이 홈 · 신작에서 빠져 있다**(기존 버그). 같은 날 Steam 순위에는 최근 14일 출시작이 5편(에이스 컴뱃 8 6위 등) 있다.
- **네이버웹툰 순위 = "오늘 요일 연재 목록 순서"**(`NaverWebtoonRankingFetcher:50`) — 어제와 비교할 수 없다. 출처 표기는 "오늘(일) 연재 인기". 네이버 시리즈는 **일간** Top 100.
- 순위 쿼리는 연결 안 된 행을 성인 판별 없이 남긴다(운영 시리즈 18 · 웹툰 14 · 영화 15행) → 트렌드는 **연결된 행만** 보인다(홈과 같다).
- 캐시 매니저는 만료가 없다(`CacheConfig`) → 서버 캐시 대신 `Cache-Control`.
- 순위 응답에 세로 표지 · 신선한 평가 값이 없다 → 응답에 더한다.
- 탐색은 `/explore` · 모르는 값을 `domain=game` 으로 정규화한다(`explore-page.tsx:39, 486-498`). 웹 하단 탭 노출 목록 `public-layout.tsx:9-15`. 내 컬렉션은 `/collections?tab=mine`, 내 리뷰 API `/api/my/reviews` 가 이미 있다. 앱 홈 `(tabs)/index.tsx:290` 이 `/(tabs)/new` 로 간다(typedRoutes).
